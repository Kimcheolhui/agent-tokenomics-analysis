# REPORT 문체 규칙

REPORT의 모든 문장에 적용한다. 요약(`meta.summary`), 증상·원인 이름, 판정 규칙(`rule`), 발견(`finding`), 판정 근거(`basis`), 감별(`differential`), 낭비 추정식(`formula`, `inputs`), 그림의 제목·부제·주석이 대상이다. `review.json`에 사람이나 Agent가 쓰는 문장도 같다.

목표는 비유와 AI 특유의 상투 표현을 빼고, 지표 값과 기준으로 직접 서술하는 것이다. 이 문서의 목록은 작성자를 판정하는 기준이 아니라 교정 체크리스트다. 사람이 쓴 글에도 같은 표현이 나오고, 목록의 표현이 없어도 AI가 쓴 글일 수 있다.

## 어떻게 쓰는가

- 한 문장에 사실 하나를 쓴다. 사실은 지표 이름, 값, 기준, 원인 ID로 쓴다. 예: "support-router의 보존 시간 내 턴 첫 호출 815건 중 420건(52%)이 캐시를 쓰지 못했다."
- 판단을 쓸 때는 근거가 되는 값과 기준을 같은 문장이나 바로 다음 문장에 쓴다.
- 확인하지 못한 것은 확인하지 못했다고 쓴다. 완곡하게 돌려 말하지 않고 판정 라벨(`후보`, `판정 보류`, `미점검`)로 표시한다.
- 동사는 동작을 그대로 가리키는 것을 쓴다. "포함된다", "전송한다", "늘어난다", "줄어든다", "집중된다".

## 쓰지 않는 표현

`scripts/lint_text.py`가 아래 패턴을 찾는다.

| 분류 | 예 | 대체 |
| --- | --- | --- |
| 대비 구문 | "단순한 설정 문제가 아니라 구조 문제다", "A뿐만 아니라 B", "A이기도 하고 B이기도 하다" | B를 바로 쓴다 |
| 문두 접속 부사, 맺음 표지 | "결론적으로", "종합하면", "다시 말해", "이처럼", "한편", 문장마다 "또한", "따라서", "그러나" | 삭제하고 내용만 쓴다. 관계가 필요하면 근거를 쓴다 |
| 결론을 선언하는 틀 | "핵심은 ~이다", "중요한 것은", "이유는 단순하다", "주목할 필요가 있다" | 사실을 바로 쓴다 |
| 무난한 맺음말 | "~가 중요하다", "~할 필요가 있다", "~를 고민해야 할 시점이다" | 해야 할 일을 구체적으로 쓴다 |
| 완곡한 단정 회피 | "~라고 볼 수 있다", "~것으로 보인다", "~한 셈이다" | 근거가 충분하면 단정한다. 아니면 `후보`로 표시한다 |
| 과장·마케팅 어휘 | "혁신적", "강력한", "심오한", "본질적", "패러다임", "시너지" | 수치나 사실로 바꾼다 |
| 강조 부사·평가어 | "매우", "굉장히", "상당히", "심각한" | 수치로 바꾼다 |
| 내용 없는 상투 어휘 | "다양한", "효과적인", "중요한 역할" | 몇 가지인지, 어떤 효과인지 쓴다 |
| 모호한 수량 | "수천 토큰", "다수의", "대다수", "사실상" | 측정한 수치를 쓴다 |
| 번역투 | "기능한다", "역할을 한다", "~에 의해", "~이 요구된다", "~이 강조된다" | 능동으로, 주어를 넣어 쓴다 |
| 은유 | "숨은 비용", "병목", "발목을 잡는다", "함정", "떠받친다", "조용히" | 직접 표현으로 바꾼다 |
| 움직임 은유 | "가파르게", "불어난다", "맴돈다", "밀려난다", "급락", "치솟는다" | "크게 늘어난다", "크게 낮아진다"와 같이 쓰고 수치를 붙인다 |
| 적재 은유 | "싣는다", "실린다" | "포함한다", "전송한다" |
| 집중 은유 | "몰린", "몰림" | "집중된" |
| 지시·탐색 은유 | "한눈에", "큰 그림", "들여다보면", "살펴보자" | "확인한다", "비교한다" |
| 해석 서술 | "~를 보여 준다", "~를 시사한다", "~를 방증한다" | 수치를 쓰고 해석은 판정 규칙에 맡긴다 |
| 수사 의문 | "그렇다면 무엇이 문제일까?" | 서술문으로 쓴다 |
| 서식 | 굵은 글씨, 이모지, 줄표(—)로 이은 문장 | 서식 없이 쓴다. 줄표는 마침표로 나눈다 |

기존 규칙(CLAUDE.md)과 이어진다. 한국어 문서는 "~한다" 평서문으로 쓰고, "~가 아니라 ~다"식 대비를 쓰지 않으며, "수천 토큰"처럼 범위가 모호한 표현을 기준으로 쓰지 않는다.

## 남겨 둔 용어

비유에서 출발했지만 이 분야의 용어로 굳은 말은 그대로 쓴다. 검사기도 이 말은 지적하지 않는다.

| 용어 | 이유 |
| --- | --- |
| 꼬리 턴, 꼬리 비율 | 분포의 tail을 가리키는 통계 용어다. D1의 지표 이름이다 |
| 쏠림 (A6 원인명 "트래픽 분산·쏠림") | 부하 편중을 가리키는 관용어이고 가이드의 원인 이름이다. 본문에서는 "요청이 집중된 구간"처럼 풀어 쓴다 |
| 늦은 실패 계수 | F4의 지표 이름이다. 시간 순서를 뜻한다 |
| 결정적 단계 (D3 원인명) | deterministic의 번역이다. "결정적인 역할"처럼 강조로 쓰는 경우만 지적한다 |
| 낭비, 상한, 카드 | 비용 용어, 수학 용어, 보고서 화면의 구성 요소 이름이다 |
| 재전송, 누적, 분산 | 동작을 그대로 가리킨다 |

## 검사

```bash
python3 scripts/lint_text.py out/report.json                       # 생성한 REPORT
python3 scripts/lint_text.py report/token-diagnosis-report.html    # 템플릿(REPORT 예시와 고정 문구)
python3 scripts/lint_text.py docs/some-file.md                     # Markdown 문서 (굵은 글씨와 표의 줄표는 지적하지 않는다)
```

`scripts/build_report.py`와 `scripts/validate_report.py`가 REPORT에 같은 검사를 실행하고 `[style]` 경고로 출력한다. 종단 검증(`tests/e2e.py`)은 합성 데이터로 만든 REPORT에서 지적이 0건이어야 통과한다.

패턴이 문맥을 보지 못하므로 오탐이 있다. 오탐이면 문장을 고치지 말고 `scripts/lint_text.py`의 패턴을 좁히고 이 문서의 "남겨 둔 용어"에 이유를 적는다.

패턴 목록은 아래 자료와 이 프로젝트의 기존 문체 규칙에서 가져왔다. 모두 참고 신호이고, 단어 목록만으로 작성자를 가릴 수 없다는 점이 자료에 공통으로 적혀 있다.

- [AI가 쓴 문장엔 이런 특징이 있다](https://brunch.co.kr/@webtutor/1155): 접속 부사 남용, 과장 형용사, 세 개씩 나열, 주제문 반복, 무난한 맺음말
- [AI 특유의 뻔한 말투 지우는 프롬프트](https://brunch.co.kr/@maven/527): "핵심은 다음과 같다", "이유는 단순하다", "~라고 할 수 있습니다", "~하는 것이 중요합니다"
- [클로드와 챗GPT 말투가 티 나는 이유](https://www.digitalmarketer.co.kr/insights/claude-load-bearing-vocabulary-github-pr): "기능합니다", "떠받치고 있습니다", "조용히 삼켜지고 있습니다", "단순한 A가 아니라 B", "결론적으로"
- [Wikipedia:Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing): 대비 구문, 세 개씩 나열, 중요성 부풀리기, 모호한 출처 표시
